# テスト用の資料（fixtures）

実装の確認と、自動分割・自動レイアウトの品質評価（[設計プラン §15](../docs/design.md#15-リスクと事前検証) の S2）に使う Markdown 資料。

- **必須**：仕様で決まっている結果。自動テストで確かめる（スライドの区切り、ステップ数、警告、レイアウトの指定など）。
- **目安**：計測とペナルティの重みで変わる結果。S2 で目視評価し、重みを調整する基準にする（正確な枚数、分割の位置など）。

実装後は、各資料から「スライドの一覧（ID・レイアウト・ステップ数・縮小率・元の行範囲）」を文字列で出力し、スナップショットとして保存する。意図した変更かどうかは、スナップショットの差分で確認する。

## 01-plain-document.md

**必須**
- フロントマターがないので、テーマは clean、比率は 16:9。
- 先頭にある唯一の H1 を資料タイトルとし、直後の一文を副題としてタイトルスライドを作る（1枚目）。
- `slideLevel` は 2。H2 の7つの節（目的〜付録）がそれぞれ1枚以上になる。
- `---` の直後が見出しなので、空のスライドを作らない。
- 警告は出ない。

**目安**
- 全体で 12〜17 枚。
- 「ブランチ戦略」「コミットのルール」「プルリクエスト」「よくあるトラブル」は2〜3枚に分かれ、区切りは小見出しの直前に来る。
- 「コミットメッセージは次の形式で書きます：」とその直後のコードは同じスライドに置く。「レビューでは次の点を確認します：」と番号付きリストも同じ。
- リストの途中で分けた場合は、続きのスライドに「プルリクエスト」と「レビューの観点」を表示する（「（続き）」は付けない）。
- 「コマンド早見表」（16行）は、1枚に縮小するか、見出し行を繰り返して2枚に分ける。

## 02-tech-talk.md

**必須**
- 1枚目は `:::maketitle`：左揃えで、右半分に cover.jpg を表示する。ロゴ・所属・日付（2026年11月20日）・イベント名・補足の「資料: …」を表示する。
- `#` の4つの章が章扉スライドになる（`slideLevel` は 2）。
- ステップ数：「状況」1、「クイズ」1、「やったこと」4、「残った課題」1。それ以外は 0。
- 「状況」に発表者ノートが付く。
- 「クイズ」は4列の横並び。「Before / After」は2列の横並び。「結果」は statement。
- 最後のスライドは「まとめ」の続き（`---` の後ろ）で、statement レイアウトなので引き継いだ見出しは表示しない。背景は bg-dark.jpg。
- フッターは「#frontend_lt」。

**目安**
- 全体で 19〜20 枚。
- 「計測に使ったスクリプト」は最長行が60文字を超えるので stack。1枚に収まらなければ縮小し、コードの途中では分けないのが望ましい。
- 「型チェックのキャッシュ」は文章とコードの split。

## 03-long-lecture.md

**必須**
- `::maketitle` がなく `title` があるので、先頭にタイトルスライドを自動で作る。
- `slideLevel` は 2。6つの `#` が章扉になる。「インデックスの設計」の章扉には導入文を一緒に表示する。
- 画像とキャプション、「：」で終わる文と直後のリストやコードは、別のスライドに分けない。
- 分割した続きのスライドには、節の見出しを表示する。小見出しの途中で分けた場合は、小見出しも同じ文言で表示する。

**目安**
- 全体で 30〜40 枚。
- 分割が起きるのは、「全件走査」「B-tree での検索の流れ」「複合インデックス」「インデックスの使えない書き方」「インデックスのコスト」「実行計画の例」「実行計画で見るべき項目」あたり。
- 「インデックスの使えない書き方」（12項目）は項目の間で分け、片方のスライドに1項目だけが残る分け方はしない。
- 「実行計画で見るべき項目」（14行の表）は、見出し行を繰り返して2枚に分けるか、1枚に縮小する。
- 「インデックスのコスト」は分量の近い小見出しが3つあるので、columns になる可能性がある。収まらなければ stack。
- 最後のページが数行だけになる分け方は避ける。

## 05-overrides.md

**必須**

| 節 | 期待する結果 |
|---|---|
| --- で区切る | 2枚。2枚目は見出しを引き継ぐ |
| 区切りの直後に見出しがある | 1枚。空のスライドを作らず、「次の節」が次の1枚になる |
| 1枚に収める {keep} | 1枚。縮小率が1未満。60% でも収まらない場合だけ警告 |
| `:::keep` の2つの節 | 1枚。タイトルは「前半」、後半の見出しは小見出しとして表示 |
| 一部だけまとめる | `:::keep` の中（「：」の文と3項目のリスト）は分割しない |
| 比率を指定して横に並べる | 左：右 ＝ 2：1 |
| 入れ子で横に並べる | 2列。各列は小見出し・画像・文章を縦に積む |
| 縦に並べる | 文章の下に画像（左右に並べない） |
| レイアウトと比率を指定する | split。画像が左で、画像：文章 ＝ 2：3 |
| 自動の判定を上書きする | stack（statement にしない） |
| 発表しない | エディタのプレビューには薄く表示し、発表と書き出しでは除く |
| クラスと揃え | `highlight` クラスが付き、縦方向は中央揃え |
| 画像の幅を固定する | 画像は幅 40% のまま（空いた領域に広げない） |
| 最後の見出しのないスライド | media レイアウト。引き継いだ見出しは表示しない |

- エディタでは 16 枚、発表では 15 枚。

## 06-steps.md

## 07-media.md

**必須**
- タイトル属性はキャプション（`figure` と `figcaption`）になる。
- `controls` の動画は poster.jpg を表示し、`autoplay loop muted` の動画は自動で再生する。
- YouTube の URL は埋め込みプレイヤーになる。PDF ではサムネイルとリンクになる。
- 背景の文字色：bg-dark → 明るい文字、bg-bright → 暗い文字、bg-bright＋`dim=0.6` → 明るい文字。
- `bg=left` は右半分に、`bg=right` は左半分に本文を置く。
- 縦横比が違う背景は歪めない。既定は切り取り、`pos=top` なら上を残す。`fit=contain` は黒い帯、`fill=blur` はぼかした同じ画像の帯で、全体を収める。
- 背景の動画は消音・ループで自動再生する。PDF では最初のフレームを表示する。
- 「背景と内容の多いスライド」を分割した場合、続きのスライドにも同じ背景を使う。
- 警告：「代替テキストのない画像」（代替テキストがない）、「存在しない画像」（ファイルが見つからない。スライドには枠だけを表示）。

## 11-edge-cases.md

**必須**：次の警告が出て、どの入力でも処理が止まらない。

| 入力 | 期待する動作 |
|---|---|
| フロントマターの `unknownKey` | 未知のキーとして警告 |
| 空行のない `---` | 直前の行が H2 になり、新しい節が始まる。「`---` の前に空行がない」と警告 |
| `{lyout=split}` | 文字のまま表示し、「`layout` のことですか？」と警告 |
| 文中の `{name}` | 文字のまま表示。警告しない |
| `\{step}` | 文字のまま表示。警告しない |
| `:::colums` | 「未知のコンテナ」と警告し、中身は普通に表示 |
| 閉じていない `:::row` | 次の節の見出しの直前で閉じたものとして扱い、警告。後ろの節は崩れない |
| `::toc` | 「未定義の指示」と警告し、文字のまま表示 |
| `***` と `___` | 水平線。スライドは区切らない |
| 連続した `---` | 空のスライドを作らない。この節は2枚 |
| 1枚に収まらない段落 | clean では1枚に収まる（10行）。収まらない段落を文の切れ目で分ける処理はまだないので、収まらなければ最大 60% まで縮めて警告する（設計プラン §4.2） |
| 深い入れ子のリスト | そのまま表示する |
| H4 の飛び | スライド内の小見出しとして扱う。警告しない |
| 背景が2つ | 「背景は1つだけ使う」と警告し、最初の画像を使う |
| 生 HTML | そのまま出力する |
| 脚注 | スライドの下部に表示する |
| `> [!WARNING]` `> [!TIP]` | テーマに合わせた囲み枠 |
| タスクリスト・打ち消し線 | GFM どおりに表示する |
| 中身のない見出し `##` | 「見出しが空」と警告。本文もないのでスライドは作らない |

## 12-settings.md

**必須**
- `lang: en`、bold テーマ、4:3（960×720）。`aspect` は引用符があってもなくても受け付ける。
- 各 H1 は子の見出しを持たず、直後に本文が続くので、`slideLevel` は 1 になる。
- `titleSlide: false` なので、`title` があってもタイトルスライドは作らない。
- 「Manual split」は `split: manual` なので分割せず、縮小して1枚にする。60% でも収まらなければ警告。bold テーマの文字の大きさでは 60% でも収まらないので、`mdhs build` で警告が出る（警告の確認にも使う）。
- 「Explicit break」は `---` で2枚になり、2枚目は見出しを引き継ぐ。
- アクセントカラーは `#e11d48`。「Accent color」には custom.css の `.highlight` が効く。
- custom.css の `body { background: magenta; }` は、スライドの外（エディタの画面）に効かない。
- ページ番号は表示せず、フッター「Settings fixture」は表示する。
- 全体で 6 枚。

## 13-arch.md

**必須**（M4）

| スライド | ステップ数 | 期待する結果 |
|---|---:|---|
| ファイル参照（正常時） | 4 | 図が横長なので stack（説明リストは図の下に横一列）。説明は「注文を送る」〜「結果を返す」 |
| ファイル参照（決済の障害） | 4 | 決済サービスとワーカーに赤いバッジ。ステップ3で worker → pay のパケットが3回動く |
| シナリオを省略 | 4 | 最初のシナリオ（正常時）を再生する |
| 動きのない構成図 | 0 | media レイアウト。パケット・番号・説明リストなし |
| 説明を図の横に出す（指定） | 4 | split（図 3：説明 2）。図が縮み、文字が小さくなるのでカメラが働く（ミニマップを表示） |
| コードブロックに直接書く | 3 | 上から下の配置で縦長なので split。キャッシュのバッジが「なし」→「あり」に変わる |
| 段階表示と組み合わせる | 6 | 1：図が出る（構成だけ）、2〜5：シナリオの4ステップ、6：最後の段落 |
| 書き間違い | — | 警告：未定義のノード `c`、構成にない経路 `b -> a`（点線で仮に描く）、存在しないシナリオ、1つのスライドに図が2つ |
| 障害と回復（#180） | 4 | 1：決済サービスが灰色になり、赤い「停止」のバッジ。2：worker → pay のパケットが3回（1/3〜3/3）、決済サービスの手前で止まり、× と「タイムアウト」を出して消える。ワーカーに赤い「3回とも失敗」。3：worker—pay の線が赤い破線になり、ワーカー寄りに ×。パケットは予備の決済へ。4：決済サービスが元の色に戻り、緑の「復旧」。線も元に戻り、パケットが届く |

- 配置はステップでは変わらない（ノードが動かない）。
- 戻る操作では、アニメーションせずに前のステップの状態になる。
- PDF（既定）では、通った経路にステップ番号を付けたまとめの1枚になる。止めたノード・切ったつながりは、最後の状態で出す。

## stability/（before.md → after.md）

**必須**
- 「節A」と「節C」のスライドは、ID も HTML も変わらない。節C の `layout=split media=left` も保たれる。
- 「節B」の `---` は、追加した段落の直後にあるまま（指定が内容と一緒に動く）。
- 「節B」は、after.md では `---` の前の部分が2枚以上に分かれる。変わるのは節B のスライドだけ。
